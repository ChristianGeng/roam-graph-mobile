#+title: The desktop app
#+STARTUP: showall

The notebook has the same app as the phone: the graph, layouts, search, the
node view, the AI and the edits are the same. It runs on Linux, Windows
and macOS, and reads the same notes folder as Emacs. This page lists what
differs from the phone. Installing: see
[[id:roam-graph-help-install][Install and update the app]].

* Install
Each full release has one file for each system. A pre-release has the
APK only.
- *Linux*: ~roam-graph-<version>-linux-x64.tar.gz~. Unpack it, then run
  ~bundle/install.sh~. It adds *Roam Graph* to the app menu. To update, run
  ~${XDG_DATA_HOME:-$HOME/.local/share}/roam-graph/app/install.sh --update~;
  to remove the app, run the same file with ~--remove~. Your notes,
  settings and keys stay.
- *Windows*: ~roam-graph-<version>-windows-x64.zip~. Unpack it, then start
  ~roam_graph_mobile.exe~. The app is not signed: if SmartScreen warns,
  choose *More info*, then *Run anyway*.
- *macOS*: ~roam-graph-<version>-macos.zip~. Move *Roam Graph* to
  Applications. The app is not signed: the first time, try to open it; macOS
  refuses. Then open System Settings, Privacy & Security, and choose *Open
  Anyway* for Roam Graph.

* First start
Tap *Choose org folder* and pick the folder that holds ~roam/~ (or ~roam/~
itself). The app remembers it; *Change folder* in *More*, *Folder and index* picks
another. From then on the app opens the graph at once. The app edits
the same files as Emacs. Emacs reloads a changed file with
~global-auto-revert-mode~, else it asks.

* Open in Emacs
The note's button is *Open in Emacs* instead of *Open in another app…*. It runs
~emacsclient~ at the note's heading, so Emacs needs ~(server-start)~;
without a running server, Emacs itself starts. If the app cannot start
the command at all, it says so and names *Settings*; it does not see a
later failure of Emacs itself.

The command is *Emacs command* in [[id:roam-graph-help-settings][Settings]]
(shown on the desktop only). On Windows the default is ~emacsclientw.exe~;
if Emacs is not on the ~PATH~, enter the full path. On macOS an app started
from the Dock does not see the shell's ~PATH~, so enter the full path, for
example ~/opt/homebrew/bin/emacsclient~.

* Follow Emacs
The graph can follow Emacs: when you open a note in Emacs, or move to
another node there, the app shows that node in the graph and beside it,
as a click on it would. A node the app does not know yet (a note saved a
moment ago) is shown once the app has read the folder again. While a
note, a chat or another page is open on top of the graph, the graph
stays as it is.

Emacs needs the small file ~roam-graph-follow.el~, with
~roam-graph-follow-mode~ on. The app brings it along, in the version that
matches it:
- Linux: ~~/.local/share/roam-graph/app/emacs/~
- Windows: the ~emacs~ folder next to ~roam_graph_mobile.exe~
- macOS: ~Roam Graph.app/Contents/Resources/emacs/~

*Copy Emacs snippet* in Settings copies the code for this app's folder.
On Linux, for example in Doom's ~config.el~ or in ~init.el~:

#+begin_src emacs-lisp
(let ((dir (expand-file-name "roam-graph/app/emacs"
                             (or (getenv "XDG_DATA_HOME") "~/.local/share"))))
  (when (file-exists-p (expand-file-name "roam-graph-follow.el" dir))
    (add-to-list 'load-path dir)
    (with-eval-after-load 'org-roam
      (require 'roam-graph-follow)
      (roam-graph-follow-mode 1))))
#+end_src

An update of the app updates the file too; Emacs reads the new one at
its next start. If your config already loads ~roam-graph-follow~ from a
copy of the app's repository (an older setup, for example
~use-package! roam-graph-follow~ with a ~:load-path~), remove that and
use only this code: whichever copy loads first wins, and the other is
ignored.

How it works: the app listens on 127.0.0.1 only, and writes the port and
a random secret to ~follow.json~ in its own folder, readable only by
you. Emacs reads that file and sends the secret with every message, so
no other program and no web page can steer the app. A message carries
only the node's ID; nothing is written. With the app closed, Emacs sends
nothing and shows no error. *Follow Emacs* in Settings (desktop only)
turns following off.

* Other differences
- Search inside a note: Ctrl+F (Cmd+F on macOS); Escape closes it. See
  [[id:roam-graph-help-search-in-note][Search inside a note]].
- In the graph, *right click* on a node opens the menu that a long press
  opens on a phone.
- In a note, *right click* on a heading opens its menu, with the keys.
  Click a heading to make it the current one (it is lightly marked); then:
  Alt+Shift+Left promotes it, Alt+Shift+Right demotes it, Alt+Up and
  Alt+Down move it, Shift+Left and Shift+Right change its TODO state,
  Delete deletes it, and Ctrl+Z (Cmd+Z on macOS) undoes the last change.
  The keys do nothing while the search field has the cursor. Swipes on
  headings are off on the desktop; turn on *Swipe actions on headings* in
  Settings → View to drag a heading with the mouse.
- Audio files dropped on the window, or chosen with *Open files…*, are
  transcribed as a voice memo, see
  [[id:roam-graph-help-capture][Capture and shared text]]. There is no
  notification on the desktop.
- Web links open in the web browser.
- *Share with AI* copies the text to the clipboard.
- Instead of sharing text into the app: drop text or text files on the
  window (or on a chat), *New note from clipboard* (Ctrl+Shift+V, Cmd+Shift+V
  on macOS) or *Open files…* in the graph's *More* menu. See
  [[id:roam-graph-help-capture][Capture and shared text]].
- API keys are kept in the system's secret store, see /API keys/ below.

* API keys

A key typed into the AI settings is saved in the system's secret store,
never in the notes or in a settings file:

- Linux: the system keyring (GNOME Keyring, KWallet or another Secret
  Service), unlocked when you log in.
- macOS: the Keychain.
- Windows: files in the app's data folder, encrypted with a key that
  Credential Manager holds.

When no key is saved for a provider, the app reads it from an environment
variable, the name the provider's own tools use. A key saved in the app
always takes precedence; the app never copies a variable into the secret
store. The key field then says /Read from …/ and has no /Remove/ button.

- Mistral: ~MISTRAL_API_KEY~
- Vercel AI Gateway: ~VERCEL_AI_GATEWAY_API_KEY~, then ~AI_GATEWAY_API_KEY~
- OpenRouter: ~OPENROUTER_API_KEY~
- Anthropic: ~ANTHROPIC_API_KEY~
- DeepSeek: ~DEEPSEEK_API_KEY~
- Qwen: ~DASHSCOPE_API_KEY~
- Scaleway: ~SCW_SECRET_KEY~
- Hugging Face: ~HF_TOKEN~
- Amazon Bedrock (EU): ~AWS_BEARER_TOKEN_BEDROCK~
- OpenAI (speech to text): ~OPENAI_API_KEY~
- Brave Search: ~BRAVE_API_KEY~

The app sees the variables of the process that starts it. Started from a
terminal, that is the shell's environment. Started from the app menu, the
dock or the Start menu, variables set in a shell profile such as
~.bashrc~ are not there: set them for the desktop session (for example
in ~.config/environment.d/~ in the home folder on Linux, ~launchctl setenv~ on macOS, the
user environment variables on Windows), or type the keys into the app once.
